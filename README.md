# Student Performance ML App

A modular Python 3.11, scikit-learn, and FastAPI project built from the existing `student_performance_ml_app` dataset and interface. It trains regression and classification pipelines, compares models, saves artifacts, and exposes predictions through a web form and JSON API.

## Important: leakage note

`FinalGrade` is deterministically binned from `ExamScore`: 85–100 → 0 (High), 70–84 → 1 (Good), 55–69 → 2 (Average), and 40–54 → 3 (Low). Therefore, models trained with `ExamScore` can score very highly because the feature directly encodes the target. These are **leakage-inflated scores**, not evidence that the other student attributes independently predict grades. The default `use_exam_score: true` is retained because the existing app form includes this input, and the training pipeline also runs an experiment with it disabled. Compare both results in `models/model_comparison.json` and `notebooks/02_modeling.ipynb`. Without ExamScore, performance should be near chance for classification (roughly 25% accuracy); actual values are computed on this dataset when you train.

## Models

Each saved estimator is a complete scikit-learn `Pipeline` containing a `ColumnTransformer` and model. Imputation, scaling, and one-hot encoding are fitted within training/CV folds; test data is not used to fit preprocessing.

### Linear Regression (regression only)
A linear baseline that predicts a numeric code from 0 to 3. It is simple and interpretable but cannot model complex nonlinear relationships. Uses `LinearRegression`; reports R², MAE, and RMSE.

### Decision Tree (regression and classification)
Learns a set of if/then splits. It can capture nonlinear rules but can overfit if unconstrained. Grid searches `max_depth` in `[4, 8]` and `min_samples_leaf` in `[2]`.

### SVM / SVR (regression and classification)
Uses an RBF kernel to represent nonlinear boundaries; SVC is used for classification and SVR for regression. It is sensitive to feature scaling. Tunes `C` in `[1.0, 3.0]` and `gamma='scale'`.

### Random Forest (regression and classification)
Combines multiple decision trees to reduce the variance of one tree. Depth and leaf-size limits keep model files and overfitting manageable. Tunes `n_estimators=30`, `max_depth` in `[8, 14]`, and `min_samples_leaf=2`.

### Gaussian Naive Bayes (classification only)
Applies Bayes' rule with a conditional-independence assumption. It is fast and compact but may underperform when features are strongly related. Uses `GaussianNB` without a grid search.

## Data and evaluation

- Raw CSV: `data/raw/student_performance.csv` (copied from the supplied existing repository).
- Duplicates are removed before a stratified 80/20 split (`random_state=42`). The dataset has no date/time field, so no time-based split is appropriate.
- Regression tuning uses `KFold(5, shuffle=True, random_state=42)` with R² scoring.
- Classification tuning uses `StratifiedKFold(5, shuffle=True, random_state=42)` with macro-F1 scoring. For laptop-friendly CV, hyperparameter search uses deterministic samples drawn only from the training split (2,500 rows for most models; 1,000 for RBF SVM/SVR). Non-SVM selected models are then refit on the complete training split; RBF SVM/SVR remain sample-fitted because full-size kernel fitting is much slower.
- Metrics include R², MAE, RMSE, accuracy, macro-F1, and confusion matrices. Actual metrics are generated by your own training run and saved in `models/metrics.json` and `models/model_comparison.json`; this README does not invent results.
- The default model is selected by training-only cross-validation (R² for regression and macro-F1 for classification); the held-out test split is used for final reporting only, avoiding test-set model selection.

## Setup from a fresh clone (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python train_models.py
pytest -q
python -m uvicorn app:app --reload
```

Open `http://127.0.0.1:8000`. If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal and activate again.

## Make commands

| Make command | Windows PowerShell equivalent (no Make required) |
|---|---|
| `make train` | `python train_models.py` |
| `make test` | `pytest -q` |
| `make run` | `python -m uvicorn app:app --host 127.0.0.1 --port 8000 --reload` |

## API routes

- `GET /` — web interface
- `GET /health` — server/model status
- `GET /dataset/info` — dataset and default model metrics
- `GET /dataset/sample` — first dataset example
- `GET /api/metrics` — default metrics JSON
- `GET /api/model-comparison` — all model results with and without ExamScore
- `POST /predict/regression` — numeric code, clipped to 0–3 and rounded to 2 decimals
- `POST /predict/classification` — category name (`High`, `Good`, `Average`, `Low`)

Prediction request fields are the 15 feature names shown in `config/config.yaml`; `model` is optional. Regression choices: `linear_regression`, `decision_tree`, `svm`, `random_forest`. Classification choices: `decision_tree`, `svm`, `random_forest`, `naive_bayes`. Omit `model` to use the best model chosen during training.

## GitHub Actions dataset setup

The raw dataset is intentionally Git-ignored. To allow CI to run training on every push, create a GitHub Actions repository secret named `STUDENT_PERFORMANCE_CSV_BASE64` containing the base64-encoded CSV. On PowerShell, create the value with `[Convert]::ToBase64String([IO.File]::ReadAllBytes('data/raw/student_performance.csv'))`. Paste the resulting string into the secret. CI restores the file temporarily, runs `make train`, then runs `pytest`.

## Notebooks

Run `jupyter notebook` and open `notebooks/01_eda.ipynb` then `notebooks/02_modeling.ipynb`. They use `../data/raw/student_performance.csv`. The modeling notebook includes separate sections for each required model, charts, metric tables, and the with/without ExamScore comparison.

## Notes

Generated model files are deliberately excluded from Git to keep the repository light. Training regenerates all artifacts locally and in CI. `config/secrets.env` is ignored and should never contain secrets that you intend to commit.
